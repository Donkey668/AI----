# AI观鸟助手 Constitution

## Core Principles

### I. 前后端分离与多端复用

项目必须采用前后端分离架构。前端使用 Vite 构建 Web 应用，负责页面渲染与用户交互；
后端通过独立 API 服务承担业务计算、知识库检索和大模型调用。
前后端必须通过明确的接口契约通信。

电脑端必须使用 Electron 承载前端，交付可下载、可安装的桌面软件。
手机端必须采用浏览器内核的 WebView 套壳应用；依据现有开发文档，使用 Capacitor。
浏览器、桌面端和手机端必须复用同一套前端业务代码，将平台差异封装在适配层，
避免重复维护业务实现，以降低维护成本。

### II. 浏览器优先验证

前期开发必须直接在浏览器中验证页面、业务流程及前后端接口联调。
核心 Web 功能的开发与验证必须能够脱离 Electron 和手机套壳独立进行，
不得把桌面或手机打包作为日常 Web 功能验证的前置条件。

进入平台集成和交付阶段后，必须在相应容器中验证平台专属能力与打包结果。
浏览器验证通过不能替代 Electron 或手机套壳的交付验证。
此流程用于缩短前期反馈周期，并保留对最终平台行为的验证。

### III. 依赖受阻时先告知

当某实现方案更高效、更易维护、更符合本章程，且采用它的唯一阻碍是缺少所需依赖时，
必须在退而使用劣等备选方案之前告知用户，不得静默降低方案质量。

告知内容必须包括首选方案及其优势、缺少的依赖、安装或启用方式，
以及备选方案的维护或性能代价。依赖需要授权时，按环境权限要求申请授权；
等待期间可以继续不依赖该决策的工作。
不得将尚未核实的依赖问题直接视为必须降级的理由。

## 技术与交付约束

- Web 前端构建工具为 Vite，桌面容器为 Electron，手机容器为 Capacitor WebView。
- 共享前端必须支持电脑与手机的响应式布局；平台桥接代码必须与共享业务逻辑分离。
- 后端作为独立 API 服务实现；客户端通过配置选择服务地址，避免与某一容器绑定。
- 改变上述架构、构建工具或容器选型，必须先修订本章程并获得用户明确认可。

## 开发流程与合规检查

1. 编写规格与实施计划时，明确共享 Web 功能、后端接口和平台专属能力的边界。
2. 实施计划必须检查前后端分离、多端复用、浏览器验证路径及所需依赖是否满足章程。
3. 前期先完成浏览器功能验证与接口联调，再按交付需要进行容器集成验证。
4. 遇到第三项原则规定的依赖阻碍时，先告知用户，再决定后续方案。
5. 审查与交付说明必须记录已完成的验证及尚未验证的平台能力，
   不得将单一平台的验证结果表述为全部平台均已通过。

## Governance

本章程约束项目后续规格、计划、任务拆分、实现和审查。
发现开发文档或实施方案与章程冲突时，必须明确指出并使方案符合章程；
如需改变章程要求，必须取得用户明确认可后修订，不得自行绕过。

每次修订必须记录变更内容、理由、受影响的原则及迁移要求，并更新版本与修订日期。
版本遵循语义化规则：删除或不兼容地重定义原则升主版本，
新增原则或实质扩展约束升次版本，仅澄清措辞或修正错误升补丁版本。
规格与计划评审必须检查章程合规性；发现不合规方案时，必须修正方案或先完成章程修订。
